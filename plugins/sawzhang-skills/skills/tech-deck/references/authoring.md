# 内容规范 — 一场技术分享该怎么写

`visual-spec.md` 管版式，这一份管**说什么、按什么顺序说、拿什么证**。
版式过了体检但内容是流水账，deck 照样是废的。

---

## 1. 骨架：四幕

| 幕 | 回答的问题 | 页数占比 | 典型页型 |
|---|---|---|---|
| 一 · 问题 | 为什么值得占用你们 25 分钟 | 15% | `A-hero` 现状图 / `B-compare` 现状 vs 期望 |
| 二 · 方案 | 我们做了什么，为什么是这个做法 | 35% | `A-hero` 骨架图 · `B-compare` 取舍 · `E-code` 关键改动 |
| 三 · 证据 | 凭什么相信它成立 | 35% | `C-dense` 证据表 · `E-code` 真实输出 · `B-compare` 前后 |
| 四 · 收束 | 听完你们要做什么 | 15% | `D-close` |

**先写第四幕。** 收束页写不出来，说明这场分享还没有结论，前面三幕写多少都是白写。

转场页（`section.html`）只在幕与幕之间放，一场最多 3 张。

## 2. 页型配比（硬要求）

- 四种正文页型 `A / B / C / E` **至少各出现一次**。全 deck 只有一种页型 = 听众第五页开始走神。
- **每场至少一页 `D-close`，放在最后。**
- **纯文字页不许存在**（`measure.js` 会 NOTE）。一页里至少有一个表 / 图 / 代码块 / 终端输出。
- 连续两页用同一种页型时，检查是不是可以合成一页。

## 3. 每一页的三件套

```
眉标   03 · 本页在讲什么          ← 一个名词短语，不是句子
标题   改动只有一处：把同步调用换成入队   ← 写结论，不写标签
导语   一句话，听众只记得住这一句      ← 没有它就说明这页没结论
```

- **标题写结论，不写标签。** ❌「性能优化方案」→ ✅「延迟不在下游，在我们自己的同步等待上」
- 一页只讲一个论点。第二个论点自然会挤到第二页去。
- 图是用来**支撑那句结论**的，不是用来填版面的。图和结论对不上，删图或改结论。

## 4. 数字与出处

这是技术分享和 marketing deck 的分界线。

1. **每个数字都要能追到出处**，写在 footer 中段：「哪个文件 · 哪一节 · 复核日期」。
   追不到出处的数字，要么去追，要么不写 —— 不许"大概"、"约"、"业界普遍"。
2. **截断轴必须在图头声明**（`.axis-note`）。把 50% 映射到 0、95% 映射到 100 还不说，
   就是在用视觉夸大差距。
3. **不可比的数不许合成一个结论**。同一指标用不同口径量出来的两个数
   （例：同一个仓库我数 48,960 行、分析文档记 19,403 行），**不许相减、不许说"增长"**，
   只能并列并注明口径不同。
4. **"找不到"要能当证据用，前提是先说清自己找过哪儿**。若结论是"官方从未公布过这个数字"，
   必须同时写出复核范围与方法（查了哪些页面、什么时候、为什么静态抓取拿不到），
   否则那句话没法验证。
5. 压测/基准数据要写清**样本量、并发、机器规格**，并注明能不能拿去承诺 SLA。

## 5. 代码页怎么写

- **只贴要讲的那几行。** review ≤ 24 行、talk ≤ 12 行，超了 `measure.js` 会提醒。
  整屏倾泻的代码等于没贴 —— 听众在找你说的是哪一行。
- 用 `.on` 高亮重点行，用 `.add` / `.del` 表示改动。行号由 `<ol start="42">` 自动出，**别手写**。
- 着色可选（`.k` 关键字 / `.f` 函数 / `.s` 字符串 / `.c` 注释），不上色也合规。
  与其花时间上色，不如把无关的行删掉。
- **代码和它的证据放同一页**：左边 diff，右边终端输出或指标。避免"说了但没证"。
- 终端输出用 `.term`，保留真实的失败行（`.out.err`）—— 只贴成功输出的页面不可信。

## 6. 反模式

| 反模式 | 为什么坏 | 改法 |
|---|---|---|
| 标题写"XX 介绍""XX 方案" | 听众读完标题不知道你的结论 | 标题写结论 |
| 一页三个论点 | 讲的时候必然超时，听的时候必然记不住 | 拆页 |
| 只讲收益不讲代价 | 评审会上第一个问题就是代价，答不上来全场崩 | 每个方案页配一个 `.cbox.warn` |
| 架构图画了但不说本次改哪 | 图变装饰 | `.focus` 标出改动层，`.dim` 标出缺口 |
| 数字没有出处 | 被追问一次就失去全部可信度 | footer 写清来源 |
| 附录堆原始数据 | 没人看，还撑大文件 | 附录只放"会被追问的那几张表" |
| 最后一页是"谢谢观看" | 浪费最贵的一页 | 换成 `D-close` |

## 7. 收束页必须回答的三件事

`D-close` 的三个 `.cbox` 对应：

1. **已经做到** — 带数字，带口径
2. **还没做** — 主动说缺口，比被问出来强
3. **需要你们做** — 具体到"谁、改什么、什么时候"

后面再挂一行 `.takeaways` 写下一步的时间点。听众带走的就是这一页。
